# Tetherball AI character startup

`tetherball_ai_init.rs` ports the 308-byte `MGTetherball::InitializeAI` helper at `0x8039bbec`. It returns without effects when the typed player count is already two or more. Otherwise it always spawns the supplied character, allocates and constructs a tetherball AI entity when allocation succeeds, registers and binds that entity, writes its ball handle, computes the heading direction through the native angle/sine-cosine path, appends the AI and character handles, marks the new slot as spawned, and increments the shared character count.

The API reuses `PlayerInitServices`, `PlayerInitInput`, and `PlayerInitState` so player and AI startup share the existing host service boundary and `+0x130` slot owner. It intentionally does not look up/reuse the WorldMan player character, configure single/multiplayer ability, set controller state, or increment +0x40; those belong to the separate `InitializePlayer` path. The caller later invokes `TetherballAIEntity::Initialize` separately.

The oracle executes the full helper and its native angle wrapper/`AsDir` math. It hooks only character spawning, AI pool/constructor/registration/binding, and CharacterState::SetDir. The 21-case fixture checks both append slots, boundary counts 2/3/255, untouched session/other handle slots, direction bits, service order, the raw character-control pointer passed to SetAIEntity, and direct object stores. The allocator always returns a valid nonzero entity in this successful-path corpus. Native allocation failure was examined but excluded from the safe fixture: the routine skips construction yet still writes entity +0x60, which dereferences null if the returned pointer is zero. The typed adapter forwards zero to `set_ai_ball_handle`; a host must surface that invalid-pointer fault.

Run `py -3.14 tools/tetherball_ai_init_oracle.py --check` from `_bevy`; the fixture pins ELF SHA-256 `5cef3efc7005fb71fed0a75e60ee240ee6ac4243b00dd3296e6e53ca269a3e2c`. This is the helper body only; top-level world/asset/camera setup and the later AI tuning initialization remain separate.
