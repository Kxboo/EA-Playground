# Original character animation graph

`animation_graph.rs` projects the CSV `AnimationStateGraph::InitializeStateGraph` routine at `0x803c92d8`. Animation state IDs come from the executable's 246-pointer `sAnimStateNames` table (`0x804eb124`), not animation bank indices. Unknown strings return the native sentinel 247; slot 246 is not searched. State names are compared exactly. The native `AnimBank::GetAnimIndex` (`0x803fca94`) uses case-sensitive binary search.

The CSV loader prepends `S_` to each asset alternative, attempts at most two alternatives, retains successful indices in order and ignores unknown state names. It clears the clip count before looking up assets. If neither lookup succeeds, existing metadata remains but the clip count is zero. If a lookup succeeds, it sets looping, reverse, random-start, frame-time, blend, start, trim, next-state, two event slots and three prop-bone names. Disabled event slots are represented as `None`; unused old event payload bytes are deliberately not additional live state. Unsafe buffers, missing headers and malformed numeric fields return errors rather than reproduce native invalid reads.

`PlayerGraph::load` reads original `player.csv`, bank and skeleton. A caller-selected female graph applies `player_female.csv` over the base graph, following the copy/overlay path at `0x803c8fd8`. `AnimationManager::LoadAnimationAssets` (`0x803c7a7c`) prefers an `animation_states` database collection; the supplied corpus has only `base` in that class, so `player` uses the CSV fallback. Character selection still must supply the actual gender/model identity. No identity is guessed from this loader.

`tetherball_clips` requires every state from 56 through 96 to resolve and decodes each referenced clip once. Both shipped gender graphs resolve the same 41 tetherball clips. They all convert through the existing `character::animation_clip` function into Bevy curves. `tetherball_assets` now owns these clip handles, graph metadata and the 68-bone skeleton along with its ball/rope resources; installation/readiness/release include `Assets<AnimationClip>`. The base graph is stored here until the scene host supplies its selected character configuration. The converter retains its existing 30-fps sample convention; this work does not verify full native playback timing.

`tools/animation_graph_oracle.py` executes the original CSV initializer, state-name converter and bank-index search. CSV record access, CString operations and formatting are explicit synchronous services; graph stores and lookup control flow execute original PowerPC. Inputs come from the original archive and independently parsed bank names. Fixtures compare all semantically active fields in 246 slots after base load, the female overlay and synthetic unknown-state/missing-clip/alternate/event cases. The base graph resolves 235 states. Fixture source hashes and the pinned ELF SHA-256 are checked by Rust tests. An ignored local bank copy under logs supports the independent reference parser; it is not committed.

Run `py -3.14 tools/animation_graph_oracle.py --check` and `cargo test --release --offline --locked animation_graph -- --nocapture` from `_bevy`. The oracle is included in `tools/prove.py`.

Validation on 2026-09-30: native oracle regeneration/check passed, and the full offline locked release suite passed 115 tests. Both genders converted all 41 tetherball clips to Bevy curves; activity asset restart/release checks now include clip-store counts. The release executable built successfully and `--prepare-tetherball` exited 0 with readiness true and 41 installed clip entries.

Remaining host dependency: port `AnimationState::SetNextAnimState`, Update, marker/bone sampling and event dispatch before reporting a playable activity. Having correct clips does not establish blending, callback timing, root motion or hit-marker matrices. The existing locomotion character loader continues using its established three clips.
